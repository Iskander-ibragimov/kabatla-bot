# Памятка владельца: как жить с ботом «Кабатла»

Для человека, который не программирует. Все действия делаются в браузере. Ключи и пароли в этот файл, в чаты и в письма не вставляйте.

## 1. Что где живёт

| Что | Где | Зачем |
|---|---|---|
| Бот | @Kabatlabot в Telegram | Ученики пишут ему |
| Репозиторий (папка с файлами бота) | github.com/Iskander-ibragimov/kabatla-bot, закрытый | Тексты слов, программа бота, расписание задач |
| Сервер | Cloudflare: программа `kabatla-bot` и база данных `kabatla` | Бот работает здесь, в базе лежат ученики и их прогресс |
| Задачи | GitHub, вкладка **Actions** | Выкладка обновлений, озвучка слов, резервная копия |

**Общий лимит.** Бесплатный тариф Cloudflare один на два бота: этот и английский. На сутки дано 100 000 обращений к серверу и 100 000 записей в базу на оба бота вместе. Если лимит кончится, оба бота встанут до 03:00 по Москве (см. раздел 6). Когда использовано 80% записей, бот пришлёт вам предупреждение.

## 2. Секреты

Секрет — это ключ или пароль, который знает только GitHub. Хранится здесь: сайт репозитория → **Settings** → **Secrets and variables** → **Actions** → вкладка **Secrets**. Кнопка **New repository secret** создаёт секрет, карандаш рядом с названием заменяет значение. Показать сохранённое значение GitHub не умеет: если забыли, выпустите новый.

| Название | Что это | Где взять | Что сломается без него |
|---|---|---|---|
| `BOT_TOKEN` | Пароль бота | @BotFather → `/mybots` → @Kabatlabot → API Token | Выкладка остановится, бот не заработает |
| `ADMIN_TG_ID` | Ваш числовой номер в Telegram | Любой бот-подсказка, например @userinfobot, пришлёт номер в ответ на `/start` | Выкладка остановится; жалобы и служебные сообщения некому слать |
| `CLOUDFLARE_API_TOKEN` | Ключ доступа к Cloudflare | cloudflare.com → **My Profile** → **API Tokens**; тот же, что у английского бота | Не пройдут выкладка, озвучка и резервная копия |
| `CLOUDFLARE_ACCOUNT_ID` | Номер аккаунта Cloudflare | cloudflare.com → панель аккаунта (Account ID показан справа на главной странице аккаунта); тот же, что у английского бота | То же самое |
| `GROQ_API_KEY` | Ключ нейросети Groq | console.groq.com → **API Keys** | Бот работает. Свои слова, которых нет в каталоге, он переводит с помощью нейросети; без ключей он просит ученика ввести перевод самому, а команда `/gen` (карточки по теме) не работает |
| `OPENROUTER_API_KEY` | Ключ запасной нейросети | openrouter.ai → **Keys** | То же. Достаточно одного из двух ключей нейросетей |
| `AUDIO_CHAT_ID` | Необязательный. Номер канала для служебных голосовых сообщений (раздел 5) | См. раздел 5 | Ничего: голосовые сообщения приходят вам в личный чат с ботом |

Ещё один секрет, `WEBHOOK_SECRET`, вводить не нужно: выкладка сама вычисляет его из токена бота.

### Как перевыпустить токен бота

Делайте это, если токен попал не в те руки или просто потерялся.

1. В Telegram откройте @BotFather и отправьте `/revoke`.
2. Выберите @Kabatlabot. BotFather пришлёт новый токен. Старый сразу перестанет работать, и бот замолчит.
3. На GitHub: **Settings** → **Secrets and variables** → **Actions** → карандаш у `BOT_TOKEN` → вставьте новый токен → **Update secret**.
4. Откройте вкладку **Actions** → слева **Deploy** → справа кнопка **Run workflow** → **Run workflow**. Через 2–3 минуты запуск станет зелёным, и бот снова отвечает.

## 3. Как исправить слово

Слова лежат в файлах уровней: `data/levels/l01.csv` (уровень 1; остальные уровни появятся позже под именами `l02.csv`, `l03.csv` и так далее). В файле одна строка на слово. Порядок столбцов в первой строке:

`word` — слово · `transcription` — транскрипция · `pos` — часть речи · `translation` — перевод · `example_tt` — пример по-татарски · `example_ru` — перевод примера · `example_src` — откуда пример · `audio_file_id` — служебный, его не трогайте.

**Что можно менять:** перевод, пример и его перевод, транскрипцию. **Чего нельзя:** менять написание слова, переносить слово в другой уровень, удалять строку. Бот узнаёт карточку по слову: изменённое слово он сочтёт новым, а старое останется у учеников.

Татарские буквы пишите только такие: ә ө ү җ ң һ. Русские буквы, похожие на них, и латинские не подойдут: проверка не пропустит такой файл.

Шаги:
1. Откройте репозиторий → папка **data** → папка **levels** → файл `l01.csv`.
2. Найдите нужную строку (кнопка поиска страницы в браузере: Ctrl+F, на телефоне — поиск по странице).
3. Справа вверху нажмите значок карандаша.
4. Исправьте нужное поле. Запятые, кавычки и число полей в строке не трогайте: поле с запятой внутри уже стоит в кавычках, так и оставьте.
5. Нажмите зелёную кнопку **Commit changes…** и ещё раз **Commit changes**.
6. Через 2–3 минуты бот обновится. Проверьте: вкладка **Actions**, запуск **Deploy** должен быть с зелёной галочкой. Если красный, проверка нашла ошибку в файле: старые карточки остаются как были. Откройте отчёт (раздел 6), раздел «catalog validation» покажет, какая строка не прошла.

**Важно: исправьте и вторую копию.** Файлы уровней собираются из общего списка `data/wordlist.csv`. Если разработчик когда-нибудь пересоберёт уровни, исправление, сделанное только в `l01.csv`, пропадёт. Поэтому правьте ту же строку ещё и в `data/wordlist.csv` (найдите её по слову; порядок столбцов там другой: `word, pos, translation, example_tt, example_ru, example_src, count, origin, transcription`). Транскрипцию вписывайте в последний столбец. Если вам это сложно, исправьте только `l01.csv` и сообщите разработчику, какое слово вы поправили.

## 4. Жалобы «⚑»

На каждой карточке есть кнопка ⚑. Ученик нажимает её, если в карточке ошибка. Одна жалоба от одного человека на одно слово.

- Сразу после нажатия вам в чат с ботом приходит сообщение: слово, перевод, пример, номер карточки и номер ученика.
- Последние 10 жалоб собраны в команде `/admin` (она работает только у вас).

Получили жалобу и согласны с ней: исправьте слово по разделу 3. Не согласны: ничего делать не нужно.

## 5. Озвучка

Новые слова озвучиваются сами. Голос Алсу, сервис speech.tatar. Запускается так:
- после каждой выкладки, если есть слова без звука;
- каждые 6 часов;
- вручную: вкладка **Actions** → слева **voice-db** → **Run workflow** → **Run workflow**.

Озвучиваются и слова каталога, и слова, которые добавили ученики. Слово, которое три раза подряд не удалось озвучить, пропускается. Готовые голоса хранятся в самом Telegram, а их номера записаны в базе.

**Куда приходят служебные голосовые сообщения.** Чтобы получить номер голоса, бот отправляет каждое озвученное слово в один чат. Если секрета `AUDIO_CHAT_ID` нет, это ваш личный чат с ботом: после выкладки уровня туда придёт много голосовых сообщений. Это нормально, их можно не слушать; можно отключить звук чата.

**Как завести отдельный канал (по желанию).**
1. В Telegram создайте новый закрытый канал.
2. Добавьте @Kabatlabot в канал администратором (право «Публикация сообщений»).
3. Узнайте номер канала: перешлите любое сообщение из канала боту-подсказке (например @userinfobot). Номер канала — число, которое начинается с `-100`.
4. На GitHub создайте секрет `AUDIO_CHAT_ID` с этим числом (раздел 2).

## 6. Как понять, что всё в порядке

**Вкладка Actions.** Репозиторий → **Actions**. Зелёная галочка — запуск прошёл, красный крестик — нет. Названия задач: **Deploy** (выкладка), **voice-db** (озвучка), **Weekly D1 backup** (копия), **CI** (проверка кода).

**Отчёты.** Это короткие текстовые файлы, в них нет ключей:
1. Репозиторий → кнопка выбора ветки (слева над списком файлов, на ней написано `master`).
2. Выберите ветку `deploy-report` и откройте файл `deploy.md`: итог последней выкладки, у каждого шага статус `success` или `failure`, внизу раздел Telegram (имя бота, совпадает ли адрес вебхука).
3. Ветка `voice-db-report`, файл `voice-db.md`: сколько слов озвучено и сколько осталось.

**Красный запуск.** Откройте отчёт: первый шаг со статусом `failure` и есть причина. Самое частое:
- `check secrets` — не хватает секрета из раздела 2;
- `load catalog` — ошибка в файле уровня (раздел 3);
- шаги Cloudflare — истёк или неверен `CLOUDFLARE_API_TOKEN`.

Красная озвучка бота не останавливает: учеников она не касается. Красная выкладка обычно тоже не ломает бота: он продолжает работать с прошлой версией. Чтобы повторить запуск, нажмите **Run workflow** (раздел 2, шаг 4). Если причина не понятна, перешлите разработчику название шага из отчёта. Ключи пересылать не надо.

**Сообщение «Технический перерыв».** Ученики видят его, когда исчерпан дневной лимит бесплатного Cloudflare (напомню: лимит общий с английским ботом). Бот сам начнёт отвечать после 03:00 по Москве, прогресс не теряется. Ничего делать не нужно. Если это повторяется каждый день, скажите разработчику: возможно, нужен платный тариф Cloudflare (около $5 в месяц).

## 7. Резервная копия

Каждый понедельник в 03:17 UTC GitHub сам копирует базу в файл. Копия хранится 90 дней. В ней всё: ученики, прогресс, свои слова и номера голосов. Без неё после потери базы пришлось бы заново озвучивать 2 000 слов.

Как скачать:
1. Репозиторий → **Actions** → слева **Weekly D1 backup**.
2. Откройте последний запуск с зелёной галочкой.
3. Прокрутите страницу вниз до раздела **Artifacts** и нажмите `kabatla-d1-backup`. Скачается архив с файлом `backup.sql`.

Сделать копию вне очереди: на той же странице **Weekly D1 backup** → **Run workflow**. Файл содержит данные учеников, никому его не отправляйте и не выкладывайте. Восстановлением из копии занимается разработчик.

## 8. Письмо в speech.tatar

Озвучку бот берёт у сервиса speech.tatar. Правила его использования не опубликованы, поэтому лучше спросить разрешения. Письмо отправьте с вашей почты на dev@translate.tatar. Если ответят, как указывать источник, добавьте это в `/help` бота через разработчика.
