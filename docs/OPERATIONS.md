# Памятка владельца: как жить с ботом «Кабатла»

Для человека, который не программирует. Все действия делаются в браузере. Ключи и пароли в этот файл, в чаты и в письма не вставляйте.

## 1. Что где живёт

| Что | Где | Зачем |
|---|---|---|
| Бот | @Kabatlabot в Telegram | Ученики пишут ему |
| Репозиторий (папка с файлами бота) | github.com/Iskander-ibragimov/kabatla-bot, закрытый с 6 октября 2026 года (до этого был открытым): его видите вы и те, кого вы пригласили | Тексты слов, программа бота, расписание задач |
| Сервер | Cloudflare: программа `kabatla-bot` и база данных `kabatla` | Бот работает здесь, в базе лежат ученики и их прогресс |
| Задачи | GitHub, вкладка **Actions** | Выкладка обновлений, озвучка слов, резервная копия |

**Слова бота.** Слова разбиты на пять уровней, как в английском: A1, A2, B1, B2, C1. Всего задумано около 3 850 карточек: 500, 850, 850, 800 и 850. Уровни наполняются по очереди, начиная с A1: сейчас в нём 400 карточек из 500, а уровень без карточек бот показывает как «скоро». У каждой карточки есть тема (тем двадцать и «Основа») и пример. Что учить, ученик выбирает сам командой `/levels`: уровни, части речи, порядок слов, тему.

**Выпуск уровней A1–C1.** С этим выпуском все ученики удаляются вместе с прогрессом и своими словами и начинают заново с `/start` — это ваше решение от 5 октября 2026 года; 400 карточек каталога и их озвучка остаются, а перед выпуском делается резервная копия (раздел 7). Эта копия запускается из ветки выпуска `cefr`, а не из `master`: шифрование копии появляется в `master` только вместе с выпуском, и запуск из `master` до него оставил бы на GitHub ещё один незашифрованный файл с данными учеников. Как выбрать ветку при запуске, сказано в разделе 7.

**Репозиторий закрыт 6 октября 2026 года; до этого он был открытым.** В нём есть две ветки с чужими материалами: `kfu-specs` — файлы спецификаций КФУ, по которым подбирались слова и темы, и `sources` — списки слов corpus.tatar. Лицензия у них не объявлена. Пока репозиторий закрыт, посторонние их не видят, и делать ничего не нужно. Если когда-нибудь решите открыть репозиторий снова, сначала сделайте две вещи. Первое: удалите ветки `kfu-specs` и `sources`, а с ними ветку `kfu-specs-fetch`, и отключите задачу `fetch-sources` во вкладке **Actions** (слева название задачи → «…» → **Disable workflow**) — иначе файлы появятся снова: эти задачи выкладывают их заново. Второе: удалите две незашифрованные резервные копии от 3 и 5 октября (раздел 7) — в открытом репозитории их снова сможет скачать любой пользователь GitHub. Закрытому репозиторию GitHub даёт бесплатно около 2 000 минут задач в месяц; бот тратит несколько сотен (озвучка проверяет новые слова четыре раза в день, остальное — выкладки и копия раз в неделю). Сколько потрачено, видно в **Settings** вашей учётной записи → **Billing and plans**.

**Общий лимит.** Бесплатный тариф Cloudflare один на два бота: этот и английский. На сутки дано 100 000 обращений к серверу и 100 000 записей в базу на оба бота вместе. Если лимит кончится, оба бота встанут до 03:00 по Москве (см. раздел 6). Когда использовано 80% записей, бот пришлёт вам предупреждение.

## 2. Секреты

Секрет — это ключ или пароль, который знает только GitHub. Хранится здесь: сайт репозитория → **Settings** → **Secrets and variables** → **Actions** → вкладка **Secrets**. Кнопка **New repository secret** создаёт секрет, карандаш рядом с названием заменяет значение. Показать сохранённое значение GitHub не умеет: если забыли, выпустите новый.

| Название | Что это | Где взять | Что сломается без него |
|---|---|---|---|
| `BOT_TOKEN` | Пароль бота | @BotFather → `/mybots` → @Kabatlabot → API Token | Выкладка остановится, бот не заработает |
| `ADMIN_TG_ID` | Ваш числовой номер в Telegram | Любой бот-подсказка, например @userinfobot, пришлёт номер в ответ на `/start` | Выкладка остановится; жалобы и служебные сообщения некому слать |
| `CLOUDFLARE_API_TOKEN` | Ключ доступа к Cloudflare | cloudflare.com → **My Profile** → **API Tokens**; тот же, что у английского бота | Не пройдут выкладка, озвучка и резервная копия |
| `CLOUDFLARE_ACCOUNT_ID` | Номер аккаунта Cloudflare | cloudflare.com → панель аккаунта (Account ID показан справа на главной странице аккаунта); тот же, что у английского бота | То же самое |
| `GROQ_API_KEY` | Ключ нейросети Groq | console.groq.com → **API Keys** | Бот работает. Свои слова, которых нет в каталоге, он переводит с помощью нейросети; без ключей он просит ученика ввести перевод самому, а команда `/gen` (карточки по теме) не работает |
| `OPENROUTER_API_KEY` | Ключ запасной нейросети | openrouter.ai → **Keys** | То же. Достаточно одного из двух ключей нейросетей |
| `AUDIO_CHAT_ID` | Необязательный. Номер канала для служебных голосовых сообщений (раздел 5) | См. раздел 5 | Ничего: голосовые сообщения приходят вам в личный чат с ботом |
| `BACKUP_PASSPHRASE` | Необязательный, но советуем завести. Фраза, которой шифруется резервная копия (раздел 7) | Придумайте сами: любая длинная фраза одной строкой. Сразу сохраните её в менеджере паролей | Ничего: копия шифруется ключом, который вычисляется из `BOT_TOKEN`. Но тогда после перевыпуска токена прежние копии открываются только старым токеном |

Ещё один секрет, `WEBHOOK_SECRET`, вводить не нужно: выкладка сама вычисляет его из токена бота.

### Как перевыпустить токен бота

Делайте это, если токен попал не в те руки или просто потерялся.

**Сначала — про резервные копии.** Если секрета `BACKUP_PASSPHRASE` у вас нет, копии базы зашифрованы ключом из нынешнего токена (раздел 7). После перевыпуска они открываются только СТАРЫМ токеном, а GitHub его не покажет. Поэтому до шага 1 сохраните нынешний токен в менеджере паролей (@BotFather → `/mybots` → @Kabatlabot → **API Token** показывает его) и храните 90 дней, пока живы старые копии. Если `BACKUP_PASSPHRASE` заведён, ничего сохранять не нужно.

1. В Telegram откройте @BotFather и отправьте `/revoke`.
2. Выберите @Kabatlabot. BotFather пришлёт новый токен. Старый сразу перестанет работать, и бот замолчит.
3. На GitHub: **Settings** → **Secrets and variables** → **Actions** → карандаш у `BOT_TOKEN` → вставьте новый токен → **Update secret**.
4. Откройте вкладку **Actions** → слева **Deploy** → справа кнопка **Run workflow** → **Run workflow**. Через 2–3 минуты запуск станет зелёным, и бот снова отвечает.

## 3. Как исправить слово

**Обычный путь.** Напишите разработчику (в тот чат с Claude, где делался бот): слово и что нужно изменить. Или нажмите ⚑ на карточке прямо в боте: карточка придёт в ваш чат и попадёт в `/admin` (раздел 4). Разработчик исправит файл, проверит его и выложит обновление.

**Где лежат слова.** Папка **data** → папка **catalog**: по одному файлу на уровень. Сейчас там один файл, `a1.csv` (уровень A1); у каждого следующего уровня будет свой. Одна строка файла — одна карточка. Поля в строке идут через запятую в таком порядке: слово, транскрипция, часть речи, перевод, пример, перевод примера, источник примера, тема, номер голоса (это поле пустое: номера голосов хранятся в базе). Порядок строк в файле — это порядок, в котором бот даёт слова уровня. Список тем лежит в файле `data/topics.csv`.

**Что не стоит править самому и почему.** Всё это идёт через разработчика:
- само слово: если просто переписать его в файле, бот счёл бы это новой карточкой, а старая осталась бы у учеников. Поэтому такая правка останавливает выкладку (шаг `catalog headwords`, раздел 6). Ошибку в написании самого слова исправляет разработчик через файл `data/renames.csv`: карточка остаётся той же, прогресс учеников сохраняется, слово озвучивается заново;
- пример и откуда он взят: пример обязателен у каждой карточки, у фраз тоже, и проверяется автоматически (каждое его слово должно быть в списке слов из корпуса, нужен перевод примера и правильная пометка источника, одно предложение нельзя поставить в две карточки);
- транскрипцию: знаки ударения и правила букв проверяются автоматически, а на клавиатуре ударение не набрать;
- тему: в поле стоит код темы латинскими буквами (например `food`), и он должен быть в `data/topics.csv`;
- добавление, удаление и перестановку строк: в уровне не может быть больше карточек, чем его размер (в A1 — 500), слово может стоять в каталоге только один раз. Удалить строку нельзя: карточка из бота не исчезла бы, она осталась бы у учеников вне файлов, поэтому выкладка с удалённой строкой останавливается на шаге `catalog headwords` (раздел 6);
- перенос слова в другой уровень или тему. Это возможно: карточки и прогресс учеников остаются при слове. Но место строки в файле задаёт порядок изучения, поэтому перенос делает разработчик.

### Если хотите исправить перевод сами

Только поле «перевод» (четвёртое по счёту в строке). Если боитесь что-то сломать, пропустите этот блок и напишите разработчику.

1. Откройте сайт репозитория → папка **data** → папка **catalog** → файл нужного уровня, например `a1.csv`.
2. Найдите строку со словом (Ctrl+F; на телефоне поиск по странице в меню браузера).
3. Справа над текстом файла нажмите значок карандаша.
4. Измените только текст перевода: между запятыми, которые отделяют его от соседних полей. Остальное в строке не трогайте.
5. Если в новом переводе есть запятая, весь перевод должен стоять в прямых двойных кавычках `"..."` (набирайте обычные кавычки с клавиши, а не «ёлочки» и не «английские» кавычки с наклоном: они не подойдут). Если запятой нет, кавычки не нужны. Пример (строка слова «авыл»):

   было: `авыл,аwы́л,n,"деревня, село",Мин авылда үстем.,Я вырос в деревне.,tatoeba:1055889,nature,`

   стало: `авыл,аwы́л,n,"деревня, село, аул",Мин авылда үстем.,Я вырос в деревне.,tatoeba:1055889,nature,`

   Здесь изменилось только то, что внутри кавычек. Слово «аул» взято для примера.
6. Нажмите зелёную кнопку **Commit changes…**. В окне оставьте выбранным пункт **Commit directly to the master branch** и нажмите **Commit changes**. Больше нигде править не нужно: перевод записан только в файле уровня.
7. Подождите 2–3 минуты. Вкладка **Actions**: запуски **CI** и **Deploy** с вашей правкой должны стать зелёными. После этого бот показывает новый перевод.

**Если запуск стал красным.** Сами не чините, напишите разработчику, какой файл и слово вы правили. Бот продолжает работать со старыми карточками: проверка, не прошедшая, ничего не загружает. Если интересно, что не так: откройте отчёт `deploy.md` (раздел 6), блок «catalog validation». Строка вида `a1:5 …` значит: файл `a1.csv` (уровень A1), пятая строка файла. Заголовок с названиями полей считается первой строкой.

## 4. Жалобы «⚑»

На каждой карточке есть кнопка ⚑. Ученик нажимает её, если в карточке ошибка. Одна жалоба от одного человека на одно слово.

- Сразу после нажатия вам в чат с ботом приходит сообщение: слово, перевод, пример, номер карточки и номер ученика.
- Команда `/admin` (она работает только у вас) показывает последние 10 слов, на которые пожаловались, и сколько жалоб на каждое.

Получили жалобу и согласны с ней: передайте её разработчику (раздел 3). Не согласны: ничего делать не нужно. Жалоба на слово, которое ученик добавил сам, через файлы каталога не исправляется: это слово есть только у него.

## 5. Озвучка

Новые слова озвучиваются сами. Голос Алсу, сервис speech.tatar. Запускается так:
- после каждой выкладки, если есть слова без звука;
- каждые 6 часов;
- вручную: вкладка **Actions** → слева **voice-db** → **Run workflow** → **Run workflow**.

Озвучиваются и слова каталога, и слова, которые добавили ученики. Слово, которое не удалось озвучить после трёх неудачных попыток, пропускается. Готовые голоса хранятся в самом Telegram, а их номера записаны в базе.

**Куда приходят служебные голосовые сообщения.** Чтобы получить номер голоса, бот отправляет каждое озвученное слово в один чат. Если секрета `AUDIO_CHAT_ID` нет, это ваш личный чат с ботом: после выкладки новых слов туда придёт много голосовых сообщений. Это нормально, их можно не слушать; можно отключить звук чата.

**Как завести отдельный канал (по желанию).**
1. В Telegram создайте новый закрытый канал.
2. Добавьте @Kabatlabot в канал администратором (право «Публикация сообщений»).
3. Узнайте номер канала: перешлите любое сообщение из канала боту-подсказке (например @userinfobot). Номер канала — число, которое начинается с `-100`.
4. На GitHub создайте секрет `AUDIO_CHAT_ID` с этим числом (раздел 2).

## 6. Как понять, что всё в порядке

**Вкладка Actions.** Репозиторий → **Actions**. Зелёная галочка — запуск прошёл, красный крестик — нет. Названия задач: **Deploy** (выкладка), **voice-db** (озвучка), **Weekly D1 backup** (копия), **CI** (проверка кода).

**Отчёты.** Это короткие текстовые файлы, в них нет ключей:
1. Репозиторий → кнопка выбора ветки (ветка — отдельная копия файлов репозитория; кнопка слева над списком файлов, на ней написано `master`).
2. Выберите ветку `deploy-report` и откройте файл `deploy.md`: итог последней выкладки, у каждого шага статус: `success` (прошёл), `failure` (сломался) или `skipped` (пропущен, потому что раньше что-то сломалось). Раздел Telegram в середине файла: имя бота и последняя ошибка связи, если она была.
3. Ветка `voice-db-report`, файл `voice-db.md`: сколько слов озвучено и сколько осталось.

**Что делает выкладка, по порядку.** Названия шагов — как в отчёте `deploy.md`:
1. `install`, `typecheck`, `test` — проверка программы бота;
2. `check secrets` — на месте ли секреты;
3. `workers.dev subdomain`, `D1 database` — адрес сервера и база на месте;
4. `check catalog` — проверка файлов каталога: ошибка в каталоге останавливает выкладку здесь;
5. `catalog headwords` — сверка с базой: каждое слово, которое уже есть в каталоге бота, должно стоять в файлах уровней или быть записано как исправленное в `data/renames.csv`. Если какое-то слово из файлов пропало (строку удалили или слово переписали без записи в `renames.csv`), выкладка останавливается здесь. До конца этого шага в базе ничего не меняется;
6. `migrations` — изменения в устройстве базы;
7. `load catalog` — загрузка слов каталога в базу;
8. `deploy worker`, `worker secrets`, `webhook and commands`, `self-check` — новая программа бота, её ключи, связь с Telegram и проверка этой связи;
9. `start voicing` — запуск озвучки, если есть слова без звука.

**Блок Catalog в отчёте.** Пять строк с числами:
- `catalog levels in repo` — сколько файлов уровней в каталоге (сейчас один, `a1.csv`);
- `catalog notes in the database: before …, after …; rows in the files: …` — сколько карточек каталога было в базе до выкладки, сколько стало после неё и сколько строк в файлах каталога. В норме «после» равно числу строк в файлах и не меньше, чем «до»;
- `voiced catalog notes: before …, after …` — сколько из этих карточек озвучено;
- `notes of the old catalog the load did not find in the files` — карточки прежнего каталога (того, что был до уровней A1–C1), которые загрузка не нашла в файлах уровней: они остались в базе на временном месте. В норме 0. Это не все карточки, которых нет в файлах: карточку, строку которой убрали из файла позже, это число не считает;
- `catalog headwords missing from the files` — сколько слов каталога есть в базе, но нет ни в файлах уровней, ни в `data/renames.csv`. Считается до выкладки. В норме 0; если не 0, выкладка остановлена на шаге `catalog headwords` и в базе ничего не изменено. Сами слова (не больше двадцати) названы в журнале этого шага: вкладка **Actions** → красный запуск **Deploy** → шаг **Check that no catalog headword is missing from the files**.

Если числа не сходятся, под ними стоит строка, которая начинается со слова `WARNING`. Выкладку она не останавливает, бот работает; перешлите эту строку разработчику. `n/a` вместо числа значит, что посчитать не удалось, например выкладка остановилась раньше.

**Красный запуск.** Откройте отчёт: первый шаг со статусом `failure` и есть причина. Самое частое:
- `check secrets` — не хватает секрета из раздела 2;
- `check catalog` — ошибка в файлах каталога (раздел 3); что именно не так, написано в том же отчёте в блоке «catalog validation»;
- `catalog headwords` — из файлов каталога пропало слово, которое уже есть в боте: строку удалили или слово переписали без записи в `data/renames.csv` (раздел 3). Бот работает как раньше, в базе ничего не изменено. Напишите разработчику: он вернёт строку или запишет исправление;
- шаги Cloudflare — истёк или неверен `CLOUDFLARE_API_TOKEN`.

Красная озвучка бота не останавливает: учеников она не касается. Красная выкладка обычно тоже не ломает бота: он продолжает работать с прошлой версией. Исключение — когда сломался шаг `migrations`, `load catalog` или `deploy worker`: база уже изменена, а программа бота ещё прежняя, поэтому сразу напишите разработчику. Чтобы повторить запуск, нажмите **Run workflow** (раздел 2, шаг 4). Если причина не понятна, перешлите разработчику название шага из отчёта. Ключи пересылать не надо.

**Сообщение «Технический перерыв».** Ученики видят его, когда исчерпан дневной лимит бесплатного Cloudflare (напомню: лимит общий с английским ботом). Бот сам начнёт отвечать после 03:00 по Москве, прогресс не теряется. Ничего делать не нужно. Если это повторяется каждый день, скажите разработчику: возможно, нужен платный тариф Cloudflare (около $5 в месяц).

## 7. Резервная копия

Каждый понедельник в 03:17 по UTC (06:17 по Москве) GitHub сам копирует базу в файл. Копия хранится 90 дней. В ней всё: ученики, прогресс, свои слова и номера голосов. Без неё после потери базы пришлось бы заново озвучивать все слова каталога.

**Копия зашифрована.** Копия хранится на GitHub среди файлов задач. В открытом репозитории такой файл может скачать любой пользователь GitHub, а репозиторий до 6 октября 2026 года был открытым. Поэтому задача шифрует копию и оставляет на хранение только зашифрованный файл `backup.sql.enc`; в списке файлов запуска он называется `kabatla-d1-backup-enc`. Без ключа прочитать его нельзя.

**Ключ.** Он бывает двух видов:
- Секрет `BACKUP_PASSPHRASE`, если вы его завели. Советуем завести: **Settings** → **Secrets and variables** → **Actions** → **New repository secret**, название `BACKUP_PASSPHRASE`, значение — любая длинная фраза одной строкой, не короче 20 знаков, без пробела в начале и в конце, например пять-шесть случайных слов. Если фраза короче или в ней есть перенос строки, копия не делается и запуск становится красным. Сразу сохраните фразу в менеджере паролей: GitHub её больше не покажет, а без неё копию не открыть. Фразу потом не меняйте: копия открывается только той фразой, которая стояла в секрете, когда копия делалась.
- Если такого секрета нет, ключ вычисляется из токена бота (`BOT_TOKEN`). Тогда помните: если токен перевыпустить в BotFather, копии, сделанные раньше, открываются только СТАРЫМ токеном. Перед перевыпуском сохраните старый токен (раздел 2) — или один раз заведите `BACKUP_PASSPHRASE` и забудьте об этом.

Каким из двух ключей зашифрована копия, написано в журнале её запуска: шаг `Check that the copy can be encrypted`, строка `key: …`.

Как скачать:
1. Репозиторий → **Actions** → слева **Weekly D1 backup**.
2. Откройте последний запуск с зелёной галочкой.
3. Прокрутите страницу вниз до раздела **Artifacts** (так GitHub называет файлы, которые запуск оставил на хранение) и нажмите `kabatla-d1-backup-enc`. Скачается архив с файлом `backup.sql.enc`.

Сделать копию вне очереди: на той же странице **Weekly D1 backup** → **Run workflow** → **Run workflow**. До выпуска уровней A1–C1 в списке **Use workflow from** сначала выберите ветку `cefr` (раздел 1): из `master` до выпуска получится незашифрованная копия. После выпуска ничего выбирать не нужно.

Файл зашифрован, но в нём данные учеников: никому его не отправляйте и не выкладывайте. Фразу и токен тоже никому не пересылайте. Восстановлением из копии занимается разработчик.

**Как открыть копию (для разработчика).** В терминале, в папке вне репозитория, куда распакован архив. Фраза или токен вводятся с клавиатуры в ответ на запрос и на экране не видны; в командную строку, в файлы и в чаты их не вставляют. Строки выполняются по одной, а не вставляются все разом; из двух первых блоков нужен только один.

```bash
# Копия зашифрована фразой BACKUP_PASSPHRASE:
printf 'BACKUP_PASSPHRASE: '; IFS= read -rs BACKUP_KEY; echo; export BACKUP_KEY

# Секрета BACKUP_PASSPHRASE не было — ключ из токена бота (вместо строки выше):
printf 'BOT_TOKEN: '; IFS= read -rs BOT_TOKEN; echo; export BOT_TOKEN
export BACKUP_KEY=$(node -e 'process.stdout.write(require("node:crypto").createHmac("sha256", process.env.BOT_TOKEN).update("kabatla-d1-backup-v1").digest("hex"))')

# В обоих случаях дальше одно и то же:
openssl enc -d -aes-256-cbc -md sha256 -pbkdf2 -iter 200000 -pass env:BACKUP_KEY -in backup.sql.enc -out backup.sql
unset BACKUP_KEY BOT_TOKEN
```

Ответ `bad decrypt` значит, что ключ не тот: другая фраза или токен, выпущенный позже копии. Файл `backup.sql` после работы удалите.

**Важно: копии, сделанные до 6 октября 2026 года, не зашифрованы.** Это два запуска, от 3 и от 5 октября (первый по московскому времени сделан в ночь на 4-е); их файл в разделе **Artifacts** называется `kabatla-d1-backup`, без `-enc`. В них данные учеников в открытом виде. С 3 по 6 октября, пока репозиторий был открытым, скачать их мог любой пользователь GitHub; сейчас репозиторий закрыт, и они видны только вам. Всё равно удалите их: если репозиторий когда-нибудь откроют снова, они опять станут доступны всем. Как удалить: **Actions** → **Weekly D1 backup** → запуск → раздел **Artifacts** → значок корзины справа от `kabatla-d1-backup`. Можно удалить и весь запуск (на странице **Weekly D1 backup** значок «…» справа от запуска → **Delete workflow run**): вместе с файлом исчезнет его журнал, в котором записан номер базы.
